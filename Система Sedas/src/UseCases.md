# Описание прецедентов использования системы Sedas

## Таблица 1 – Спецификация прецедентов

| ID | Наименование | Актор | Основной поток | Альтернативный поток |
|----|--------------|-------|----------------|----------------------|
| **UC-1** | Регистрация пользователя | Администратор | 1. Администратор открывает интерфейс управления пользователями<br>2. Вводит данные пользователя<br>3. Система валидирует данные<br>4. Система создает учетную запись пользователя | 1. Администратор открывает интерфейс управления пользователями<br>2. Вводит данные пользователя<br>3a. Пользователь с таким email уже существует<br>4a. Система выдает ошибку |
| **UC-2** | Вход в систему | Администратор / Сотрудник | 1. Пользователь вводит учетные данные<br>2. Система проверяет учетные данные<br>3. Пользователь получает доступ к системе | 1. Пользователь вводит учетные данные<br>2a. Учетные данные неверны<br>3a. Пользователь получает отказ в доступе |
| **UC-3** | Создание документа | Сотрудник | 1. Пользователь инициирует создание документа<br>2. Загружает файл<br>3. Система сохраняет документ<br>4. Документ получает статус «Черновик» | – |
| **UC-4** | Отправка документа на согласование | Сотрудник | 1. Пользователь выбирает документ<br>2. Выбирает маршрут согласования и отправляет<br>3. Участники согласования получают уведомления | – |
| **UC-5** | Согласование документа | Сотрудник | 1. Пользователь открывает документ<br>2. Просматривает содержимое<br>3. Принимает решение о согласовании<br>4. Система фиксирует новый статус | 1. Пользователь открывает документ<br>2. Просматривает содержимое<br>3a. Возвращает документ на доработку<br>4a. Система откатывает статус |
| **UC-6** | Подписание документа ЭЦП | Подписант | 1. Пользователь инициирует подписание документа<br>2. Система выполняет криптографическую подпись документа<br>3. Документ получает статус «Подписан» | 1. Пользователь инициирует подписание документа<br>3a. Сертификат подписи невалиден<br>4a. Система возвращает ошибку подписи |
| **UC-7** | Проверка электронной подписи | Сотрудник | 1. Пользователь открывает документ<br>2. Инициирует проверку подписи<br>3. Система выполняет криптографическую проверку<br>4. Отображается результат проверки | 1. Пользователь открывает документ<br>2. Инициирует проверку подписи<br>3a. Подпись недействительна<br>4a. Отображается предупреждение |
| **UC-8** | Поиск документа | Сотрудник | 1. Пользователь вводит критерии поиска<br>2. Система выполняет поиск<br>3. Отображается список документов | 1a. Пользователь применяет фильтры поиска<br>2. Система выполняет поиск<br>3. Отображается список документов |
| **UC-9** | Назначение ролей | Администратор | 1. Администратор выбирает пользователя<br>2. Назначает роль<br>3. Система сохраняет изменения | – |
| **UC-10** | Настройка маршрутов документов | Администратор | 1. Администратор переходит в раздел настроек<br>2. Администратор инициирует создание маршрута<br>3. Администратор указывает параметры маршрута<br>4. Система сохраняет маршрут | 1. Администратор переходит в раздел настроек<br>2a. Администратор инициирует изменение маршрута<br>3a. Администратор исправляет параметры |
| **UC-11** | Архивация документа | Сотрудник | 1. Пользователь инициирует архивацию документа<br>3. Система перемещает документ в архив | – |
| **UC-12** &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; | Отправка системных уведомлений | Система | 1. Происходит событие (согласование / подписание)<br>2. Система формирует уведомление<br>3. Пользователь получает уведомление | – |

---

**Примечания:**

- **Актор** – действующее лицо, взаимодействующее с системой
- **Основной поток** – последовательность действий при успешном выполнении сценария
- **Альтернативный поток** – последовательность действий при возникновении исключительной ситуации или при выборе пользователем иного пути
