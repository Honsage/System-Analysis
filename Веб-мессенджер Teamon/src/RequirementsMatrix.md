# Матрица требований к программному продукту Teamon

| № | Требование | Суть | Автор | Ссылки | Критерий проверки |
|---|-------------|------|-------|--------|-------------------|
| **1** | **Работа с пользователями** | | | | |
| 1.1 | Регистрация пользователя | Система должна предоставлять возможность регистрации нового пользователя по email или через сторонние сервисы (OAuth) | Мусатов | [Информационный ресурс](https://habr.com/ru/companies/UXDepot/articles/134595/) | Пользователь может создать учетную запись, указав email и пароль |
| 1.2 | Аутентификация пользователя | Система должна обеспечивать вход зарегистрированного пользователя в систему по email и паролю | Мусатов | [Информационный ресурс](https://habr.com/ru/companies/UXDepot/articles/134595/) | Пользователь с существующим аккаунтом может войти в систему, введя корректные учетные данные |
| 1.3 | Восстановление пароля | Система должна предоставлять механизм восстановления пароля через email | Комков | [Информационный ресурс](https://en.wikipedia.org/wiki/Self-service_password_reset) | Пользователь может запросить сброс пароля, получить на email ссылку и установить новый пароль |
| **2** | **Чат и коммуникации** | | | | |
| 2.1 | Создание командного чата | Авторизованный пользователь должен иметь возможность создать новый командный чат, указав название и добавив участников | Сафаров | Анализ мессенджеров Telegram и Discord | В интерфейсе есть кнопка «Создать чат», после нажатия которой и заполнения формы создается новый чат, который отображается у всех его участников |
| 2.2 | Отправка текстовых сообщений | Участник чата должен иметь возможность отправлять текстовые сообщения в режиме реального времени | Сафаров | Анализ мессенджеров Telegram и Discord | Сообщение, отправленное одним участником, появляется у другого не позднее, чем через 3 с |
| 2.3 | Упоминание участников | Пользователь должен иметь возможность упомянуть другого участника чата в сообщении | Сафаров | Анализ мессенджеров Telegram и Discord | При указании в сообщении id участника чата, он получает уведомление |
| 2.4 | Закрепление сообщений | Участник чата должен иметь возможность закрепить важное сообщение в чате | Боханов | [Информационный ресурс](https://postmypost.io/ru/glossary/fasten/) | У выбранного сообщения есть опция «Закрепить». Закрепленные сообщения отображаются в специальном разделе |
| 2.5 | Поиск по истории сообщений | Система должна предоставлять полнотекстовый поиск по истории сообщений в чате | Комков | Анализ мессенджеров Telegram и Discord | При вводе ключевого слова в поисковую строку отображается список сообщений с этим словом. Время первого результата не более 2 с |
| **3** | **Видеосвязь** | | | | |
| 3.1 | Инициация группового созвона | Администратор чата должен иметь возможность начать групповой видеозвонок, пригласив часть или всех участников чата | Комков | [Информационный ресурс](https://habr.com/ru/companies/tbank/articles/825132/) | В интерфейсе чата есть кнопка «Начать созвон», при нажатии которой создается комната звонка, а участники получают уведомление |
| 3.2 | Качество видеосвязи | Система должна обеспечивать стабильную передачу видео и аудио | Сафаров | Анализ сервисов для групповых звонков Zoom, Google Meet и Яндекс.Телемост | При тестировании с ограничением скорости 20 Мбит/с видео не рассыпается на квадраты, звук не прерывается |
| 3.3 | Подключение к звонку | Участник, получивший приглашение, должен иметь возможность подключиться к звонку одним кликом | Комков | Анализ сервисов для групповых звонков Zoom, Google Meet и Яндекс.Телемост | При получении уведомления о звонке пользователь видит кнопку «Присоединиться», после нажатия которой он попадает в звонок |
| 3.4 | Завершение звонка | Инициатор звонка должен иметь возможность завершить звонок для всех участников | Комков | Анализ сервисов для групповых звонков Zoom, Google Meet и Яндекс.Телемост | При нажатии кнопки «Завершить для всех» все участники отключаются от звонка |
| **4** | **Управление задачами (kanban доска)** | | | | |
| 4.1 | Создание канбан-доски | В каждом командном чате должна быть доступна канбан-доска для планирования задач | Мусатов | Анализ досок для планирования Trello и Jira | В интерфейсе есть вкладка «Доска», при переходе в которую отображается доска с предопределенными столбцами |
| 4.2 | Создание задачи | Руководитель команды должен иметь возможность создать карточку задачи с указанием исполнителя | Мусатов | Анализ досок для планирования Trello и Jira | На доске есть кнопка «Создать задачу». После заполнения формы и указания исполнителя создается новая карточка задачи |
| 4.3 | Уведомление исполнителя | При создании новой карточки система должна уведомлять назначенного на нее участника | Сафаров | [Информационный ресурс](https://yandex.ru/adv/edu/materials/push-uvedomleniya-chto-eto-takoye) | При создании новой карточки назначенному участнику приходит уведомление о назначении |
| 4.4 | Перемещение задач | Участник команды должен иметь возможность перемещать карточки между столбцами методом drag-and-drop | Боханов | Анализ досок для планирования Trello и Jira | При перетаскивании карточки в другой столбец ее позиция сохраняется и синхронизируется у всех участников |
| **5** | **Файлы и дашборды** | | | | |
| 5.1 | Загрузка файлов | Участник чата должен иметь возможность загрузить файл в область проекта (до 50 МБ) | Комков | Анализ мессенджеров Telegram и Discord | В интерфейсе есть кнопка «Прикрепить файл» или область drag-and-drop. После загрузки файл отображается в списке файлов чата |
| 5.2 | Хранение файлов | Загруженные файлы должны храниться в системе и быть доступны для скачивания всем участникам чата | Мусатов | Анализ сервисов хранения данных Google Drive и Яндекс.Диск | Файл, загруженный неделю назад, доступен для скачивания в разделе файлов проекта |
| 5.3 | Дашборд проекта | В каждом чате должен быть раздел «Дашборд» для хранения полезной информации и ресурсов | Боханов | [Информационный ресурс](https://www.rbc.ru/life/news/6722aee79a79476dcf47ea95) | В интерфейсе чата есть вкладка «Дашборд», где можно добавлять информацию или ссылки |
| **6** | **Пользовательский веб-интерфейс** | | | | |
| 6.1 | Адаптивность | Интерфейс должен поддерживать адаптивность и корректно отображаться на мобильных устройствах | Боханов | [Информационный ресурс](https://habr.com/ru/companies/simpleone/articles/881168/) | При открытии сайта на мобильном устройстве интерфейс отображается корректно и доступны все элементы |
| 6.2 | Понятность | Интерфейс должен быть интуитивно понятным (максимум 2 минуты на освоение новым пользователем) | Боханов | Анализ мессенджеров Telegram и Discord | При освоении новым пользователем на понимание способа отправки сообщения уходит не более 2 минут |
| **7** | **Правовые нормы и безопасность** | | | | |
| 7.1 | Защита персональных данных | Система при сборе, хранении и обработке персональных данных должна соблюдать требования ФЗ | Комков | [Информационный ресурс](https://www.consultant.ru/document/cons_doc_LAW_61801/) | При тестировании на проникновение и анализе кода не должно быть выявлено уязвимостей, позволяющих получить несанкционированный доступ к персональным данным пользователей |
| 7.2 | Шифрование трафика | Весь сетевой трафик системы должен шифроваться с использованием протокола HTTPS | Сафаров | [Информационный ресурс](https://https.cio.gov/) | При проверке сертификата сайта и анализе сетевого трафика подтверждается использование HTTPS |
| 7.3 | Хэширование паролей | Пароли пользователей должны храниться в базе данных в зашифрованном виде с использованием bcrypt | Сафаров | [Информационный ресурс](https://kaf401.rloc.ru/Criptfiles/gost_34_11_2012.pdf) | При анализе БД пароли не читаются в открытом виде. При аутентификации сравниваются хэши |
| 7.4 | Защита от XSS | Система должна экранировать пользовательский ввод для предотвращения XSS-атак | Сафаров | [Информационный ресурс](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CSP) | Сообщения с HTML-тегами должны интерпретироваться браузером не как код, а как текст |
